# 偵測方法知識庫（AI 問答用）

本檔由 `src/web/assistant.py` 的 `lookup_knowledge` 工具依「## 」標題切段檢索。
數字取自程式預設值；程式改了參數，這裡要跟著改。

## 資料與特徵

- 每一筆模型輸入是 105 維 clean 特徵（固定維度），來源是
  `data/Step-*/myfeature/**/*_Group_feature_data_clean.csv`，本專案唯讀。
- 文件描述一秒窗；這份 clean CSV 本身沒有證明原始時間、實際取樣率、stride 或同步。
  不把文件設定當當次採集證據，也不把一筆回放自動換成一秒現場時間。
- 資料集 = 馬達代碼（T1／T2／T3）× 轉速目錄（例如 8000rpm），共 9 組，以掃描目錄為準（`core.data.discover_datasets`）。
- 已知類別切分 train/cal/holdout = 60/20/20（`core.data.make_split`），seed 預設 42。
- T1／T2／T3 有文件支持為不同馬達個體，不能串成一顆馬達的生命週期。
  187／62／64 是 T1／8000rpm 健康 313 列的指定示例；實際用量讀當次來源與模型紀錄。

## 螺絲配置（故障類別）

健康基準是 8screws（8 顆螺絲全鎖）。其餘配置代表馬達座鬆動程度：

| 配置 | 意義 |
|---|---|
| 8screws | Healthy（8 螺絲全鎖） |
| 7screws | 最輕微鬆動 |
| 6screws | 輕微鬆動 |
| 5screws | 中度鬆動 |
| 4screws | 明顯鬆動 |
| 3screws | 嚴重鬆動 |
| 2screws | 很嚴重鬆動 |
| 1screw／1screws | 最嚴重鬆動（兩種目錄名都出現過） |
| 3_14screws | 複合不均勻鬆動 |
| 4_146screws | 複合不均勻鬆動 |

## 冷啟動流程

1. 一開始只認識健康（階段 0）。
2. 每筆樣本算開集分數；超過 1.0 判為「未知」。
3. 分數超過隔離線 2.0 的未知樣本進「隔離區」；1.0～2.0 之間只警報、不參與新類發現。
4. 隔離區每累積 10 筆新樣本試一次 HDBSCAN 分群。
5. 聚出 ≥ 25 筆的穩定叢集 → 產生「候選新故障」。
6. 新類怎麼納入，看是哪個頁面：
   - 實驗頁的實驗二（▶ 執行與 ⏵ 邊跑邊畫）不等操作員確認。候選一成群就只用這一群樣本自學，
     類名是「模型新類 N」（discovered-N），不讀真實配置，也不用完整配置池。群不到 5 筆就不納入。
     群的中位分數若沒有超過已知類校準資料的最大分數，依專案規則退回不學（rejected_boundary）；
     這不是已證明兩個分布相同的統計檢定。
     學會後用新模型重新判斷隔離區，已被接受的殘餘移出；這項清理不保證新類都不重複或不混群。
     真實配置的多數與純度只放在「事後對照」，不是系統判定。
   - 首頁即時展示與獨立導覽保留「操作員確認」按鈕：按下才揭示真實身分，讀該配置的完整資料重新擬合。
     若叢集其實是已知類別的邊界樣本，回傳 rejected_known：退回、清出隔離區，量尺不變。

未納入的未知資料不參與初始擬合與校準；adopt 只用通過規則的候選群建立新類，
confirm 則使用確認後的完整標記配置池。不能把兩者的更新用量混為一談。

## 開集分數與判定

- 預設方法 Mahalanobis，逐類 Ledoit–Wolf 共變異數；可改逐類 k-NN 距離（k = 5）。
- 每類以校準集距離的第 95 百分位（confidence 0.95）當閾值，分數 = 距離 ÷ 閾值。
- 這是有限 known calibration 資料的距離分位數，不是每筆 95% 正確機率，也不保證新馬達誤報固定 5%。
- 判定：分數 ≤ 1 屬於某已知類別（健康或已學會的故障）；所有類別分數都 > 1 → 未知。
- 「相對偏離量尺」= min(1, 1/score) × 100%，只供展示，不是損壞百分比、不是剩餘壽命。

## 健康誤報率

10.9% 誤報、約 62 筆 calibration、誤報分數 1.01–1.08 及故障分數 ≥10 是指定示例的觀察，
不是所有馬達、轉速、方法與新模型的常數。誤報率與樣本量讀當次輸出；有限校準量可能影響門檻，
不能只看一個誤報比例就確定原因，也不能把未知分數大當成故障病因證明。
所以單筆偶發「未知」不代表故障；要看 EWMA 是否持續上升、隔離區是否累積。

## 變化點分析（EWMA）

- 對「是否判為未知」做 EWMA，alpha = 0.08，warmup 10 筆，視窗 120 筆（`core.trend.TrendMonitor`）。
- EWMA ≥ 0.5 觸發警報；[0.2, 0.5) 是中間帶。
- 警報當下回頭數中間帶停留筆數 transition：≤ 12 筆判「突發事件（跳變）」，否則判「漸進退化（漂移）」。
- CUSUM 只是展示用的偏移能量統計，沒有門檻。

## HDBSCAN 自適應密度階梯

- 預設 (min_cluster_size, min_samples) = (25, 3)。
- 隔離區 ≥ 75 筆加試 (15, 3)；≥ 100 筆加試 (10, 2)。候選叢集仍需 ≥ 25 筆。
- 實驗二現行走 `adopt()` 自學，並加了邊界退回與學會後清理殘餘。`output/exp2_scale_growth/2026-10-23-00-13-53/summary.json`（Aero，commit 62b6967，seed 42，T1/8000rpm）九段都學到當段注入的配置，發現延遲 51～75 筆；seed 123、2026 也都九段學到當段配置，延遲最多 118 筆。
- 每個配置先切 20% 外部評估集不參與重播。學成新類後，外部評估集被認得的比例 seed 42 是 53.8%～96.6%，最低是 7screws；三個 seed 的最低值是 53.85%、56.92%、63.49%。學成新類不代表之後都認得。
- 關掉密度階梯（`--fixed-density`）時修正無效：三個 seed 只有 2～3 段學到當段配置，最慢一段 696 筆。報告在 `reports/JW-Albert_20261023_exp2_adopt_fix_aero/README.md`。
- 實驗只在 Aero 或 Spark 主機跑；macOS 的 numpy 用 Apple Accelerate，同 seed 數字不同（issue #224），不拿來引用。
- 畫面顯示「已試分群 N 次」代表隔離區仍在累積、還沒成群。

## 極座標健康地圖（方向與半徑）

- 方向 = 與各已知故障「射線」的 cos 相似度，最接近的射線代表最像哪種已知故障；cos 越低方向越陌生。
- 半徑 = 偏離健康中心的距離，代表嚴重度。
- 量尺擴張後 PCA 投影會改變，前端會清空散佈圖，屬刻意行為。

## 偵測統計的讀法

- 學會前偵測率：某故障被學會之前，被判未知的比例（越高越好）。
- 首頁／導覽的學會後接受率：學會後被判為任一 known 的比例，不要求判對自身配置，不表示恢復健康。
- 實驗二 `own_holdout_acc`：群內保留列被判對新模型類別的比例，分母為 `own_holdout_n`；不是未知召回。
- `eval_known_rate`／`final_eval.known_rate`：未參與重播的外部配置列被任一新類接受的比例，
  不要求判成自身配置對應的特定類。`eval_n` 或 `final_eval.<配置>.n` 是其保存分母。
- `matched`／`cluster_purity`：候選真值多數／占比，只供事後對照，不是線上辨識出物理故障原因。
- `confidence=0.95` 不能推出學會後必達 90–95%；群內正確率、外部接受、未知召回與純度須分開。
  沒有連續分數、真值與相同模型／資料角色，不能由上述彙總比例推估未知 AUROC。

## 處置建議原則

- 系統只判「已知／未知」與「漸進／突發」，不會自動給出故障根因。實驗二自學的新類只有「模型新類 N」這個名字，對應哪種螺絲配置要人看事後對照判斷。
- 出現候選新故障時：檢查叢集大小、純度、樣本蒐集區間；蒐集區間偏舊可能是健康期誤報累積。
- 「突發事件」警報建議立即停機檢查固定件；「漸進退化」建議排程檢修並持續觀察 EWMA。
  以上處置屬本專案操作約定，現場規範以維修手冊為準。
